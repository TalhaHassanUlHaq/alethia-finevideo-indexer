# Implementation Task: Phase 3 Reference Test Set

## Objective

Build a reproducible local reference suite so every later optimization can be
compared against stable answers generated by the verified all-frame FP32
baseline. Codex owns candidate selection, acceptance review, and the eventual
GPU reference run. Gemini implements only the bounded infrastructure below.

## Required implementation

### 1. Reference fixture builder

Add a script that:

- Accepts the local FineVideo shard directory and an output directory.
- Reads only the selected source rows.
- Writes a deterministic compact Parquet fixture under ignored
  `artifacts/reference/input/`.
- Uses a stable fixture filename and stable row order from the selection file.
- Preserves both `mp4` and `json` columns.
- Writes an artifact manifest containing source filename, source row, fixture
  row, duration, resolution, FPS, reason, payload SHA-256, and fixture SHA-256.
- Refuses to overwrite incompatible artifacts unless an explicit safe
  `--force` option is passed.

### 2. Media probe

Add a script or reusable function that probes every fixture video using PyAV
and records:

- Decoded frame count.
- First and last usable timestamps.
- Observed elapsed final second.
- Stream/frame rate.
- Encoded and decoded dimensions.
- Rotation value observed on decoded frames.

Write this data to ignored `artifacts/reference/probe.json`. The probe must
fail if it cannot decode every selected video. It must also report whether at
least one video has a nonzero rotation tag. Do not claim portrait resolution is
a rotation tag. A missing nonzero tag is an acceptance warning for Codex, not a
reason to alter the frozen selection automatically.

### 3. Full-frame reference generator

Add a thin script that invokes the existing production pipeline with:

- Official `yolo11l.pt`.
- All frames.
- Image size 640, confidence 0.4 and NMS IoU 0.7 through existing production
  code.
- FP32.
- Batch size 1.

It must produce:

- `reference/expected.jsonl` (stable reference answers).
- `reference/metadata.json` containing fixture, result, model-weight and source
  hashes; model settings; package versions; device; and elapsed time.

Generation must be explicit and must not happen during unit tests. Do not
duplicate aggregation or inference logic in the generator—call the existing
pipeline entry point.

### 4. Reference comparator

Add a script that compares a candidate JSONL against the stable reference and
reports:

- Record-key coverage and unexpected/missing records.
- Object true positives, false positives, false negatives and micro F1.
- People exact-match rate.
- People-within-one rate.
- Exact record-match rate.
- Error records and schema failures.

Support an `--exact` mode that exits nonzero on any difference. The default
mode must exit nonzero if assignment thresholds are missed: object F1 below
0.95, people exact below 0.85, or people within one below 0.95.

### 5. Tests and documentation

- Add unit tests using tiny synthetic Parquet/JSONL fixtures; never invoke
  YOLO, access the network, or scan the full FineVideo dataset in tests.
- Test deterministic selection order and hashes, missing rows, comparator
  metrics, exact-mode failure, threshold failure, schema errors, and successful
  equality.
- Add `REFERENCE.md` with exact build, probe, generate, validate, and compare
  commands. Clearly distinguish tracked files from ignored generated data.
- Update `.gitignore` only if needed to keep video payloads, weights and bulky
  generated artifacts out of version control while retaining the small stable
  expected results and metadata.

## Constraints

- Follow `AGENTS.md`.
- Do not edit production behavior unless a test exposes a confirmed defect.
- Do not edit `WRITEUP.md`, `.env`, model settings, Phase 2 evidence, or Kaggle
  resources.
- Do not perform research, choose different videos, annotate data, skip frames,
  add FP16, batch inference, or begin optimization.
- Never print or copy credentials.
